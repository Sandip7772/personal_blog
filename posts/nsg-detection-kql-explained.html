The NSG change detection query, explained piece by piece

In the previous post I covered how the Azure Activity Log records an NSG change: three rows per change, no payload on deletes, create and modify looking identical. This post shows how the query is built around those facts.

The full query is around 100 lines, which is hard to read in one go. Here it is in the order I would explain it to a colleague.

1. Settings at the top

let report = 1h;
let SubNames = datatable(SubId:string, SubscriptionName:string)
[
    "00000000-0000-0000-0000-000000000000", "Example subscription",
];

report is how far back each run looks for changes to alert on. It must equal the rule's run frequency, which I explain in the next post. SubNames is a lookup, because AzureActivity only carries the subscription ID. I generate the rows with the Azure CLI rather than typing them:

az account list --all --query "sort_by([].{id:id, name:name}, &name)" -o table

2. The operations we care about

let WriteOps = dynamic([
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/WRITE",
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/SECURITYRULES/WRITE"
]);
let DeleteOps = dynamic([
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/DELETE",
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/SECURITYRULES/DELETE"
]);
let AllOps = array_concat(WriteOps, DeleteOps);

Both the whole NSG and the individual security rule can be written or deleted, so all four operations are listed. There is no separate create operation, as explained last time.

3. A pool of payloads (the Start and Accept rows)

let Bodies =
    AzureActivity
    | where OperationNameValue in~ (WriteOps)
    | extend Req  = tostring(Properties_d.requestbody),
             Resp = tostring(Properties_d.responseBody)
    | extend Rank = iff(isnotempty(Req), 1, 2),
             Body = iff(isnotempty(Req), Req, Resp)
    | where isnotempty(Body)
    | summarize arg_min(Rank, Body) by CorrelationId
    | project CorrelationId, Payload = todynamic(Body);

This collects the rule definition for every write. It prefers the requestbody from the Start row and falls back to the responseBody from the Accept row. arg_min picks one payload per CorrelationId. Note that this pool has no ago(report) filter. It spans the whole lookup window so the Start row is still reachable when its Success row lands near the edge.

4. The confirmed changes (the Success rows)

let Confirmed =
    AzureActivity
    | where TimeGenerated > ago(report)
    | where OperationNameValue in~ (AllOps)
    | where ActivityStatusValue =~ "Success"
    | extend Entity = tostring(Properties_d.entity)
    | extend Ev = Authorization_d.evidence
    | project TimeGenerated, CorrelationId, OperationNameValue, Caller,
              CallerIpAddress, SubscriptionId, ResourceGroup, Entity,
              DisplayName   = tostring(Claims_d.name),
              RoleUsed      = tostring(Ev.role),
              PrincipalType = tostring(Ev.principalType),
              MfaSatisfied  = tostring(Claims_d["http://schemas.microsoft.com/claims/authnmethodsreferences"]) has "mfa";

This is the set that generates alerts. Filtering to Success stops triplicate alerts, and ago(report) limits it to the reporting window. It also pulls the "who" from the caller details: the display name, the Entra role used, the principal type, and whether MFA was part of the sign-in. Treat that last one as a hint, not proof, because it reflects authentication at token issuance.

5. Deletes: a separate branch

let DeleteRows =
    Confirmed
    | where OperationNameValue in~ (DeleteOps)
    | extend ChangeType = iff(OperationNameValue endswith "SECURITYRULES/DELETE",
                              "Deleted (rule)", "Deleted (whole NSG)")
    | extend NSGName  = extract(@"(?i)networkSecurityGroups/([^/]+)", 1, Entity),
             RuleName = extract(@"(?i)securityRules/([^/]+)", 1, Entity)
    | extend Priority = int(null), Direction = "n/a", Action = "n/a", Protocol = "n/a",
             SourceIP = "n/a", SourcePort = "n/a", DestinationIP = "n/a", DestPort = "n/a",
             Description = "", Exposure = "Review";

Deletes have no payload, so the rule detail is filled with n/a and the exposure is marked Review. The NSG and rule names come from the resource path instead.

6. Writes: join, expand, extract

let WriteRows =
    Confirmed
    | where OperationNameValue in~ (WriteOps)
    | join kind=inner Bodies on CorrelationId
    | extend RuleSet = iff(isnotnull(Payload.properties.securityRules),
                           todynamic(Payload.properties.securityRules),
                           pack_array(Payload))
    | mv-expand Rule = RuleSet
    | extend p = Rule.properties
    | extend RuleName  = tostring(Rule.name),
             Etag      = tostring(Rule.etag),
             Direction = tostring(p.direction),
             Action    = tostring(p.access),
             Protocol  = tostring(p.protocol),
             Priority  = toint(p.priority),
             Description = tostring(p.description)
    | extend ChangeType = iff(isempty(Etag), "Created", "Modified")

This joins each confirmed write to its payload on CorrelationId, expands the rule set (one rule or a whole NSG's worth) and extracts the fields. The etag check labels created vs modified.

Sources, destinations and ports can each be a single value, a list, or an application security group, so a case() picks whichever is populated. For example, for the source:

| extend SourceIP = case(
        array_length(todynamic(p.sourceAddressPrefixes)) > 0,
            strcat_array(todynamic(p.sourceAddressPrefixes), ", "),
        array_length(todynamic(p.sourceApplicationSecurityGroups)) > 0,
            strcat("ASG: ", strcat_array(extract_all(
                @'applicationSecurityGroups/([^/"]+)',
                tostring(p.sourceApplicationSecurityGroups)), ", ")),
        tostring(p.sourceAddressPrefix))

Wildcards (*) are then replaced with Any so the exposure check and the alert text read naturally.

7. Grading the exposure

| extend Exposure = case(
    Direction =~ "Inbound" and Action =~ "Allow"
        and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0")
        and DestPort in ("22", "3389"), "Critical",
    Direction =~ "Inbound" and Action =~ "Allow"
        and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0")
        and DestPort == "Any", "Critical",
    Direction =~ "Inbound" and Action =~ "Allow"
        and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0"), "High",
    "Normal")

An internet-sourced inbound Allow to SSH, RDP or any port is Critical. Any other internet-sourced inbound Allow is High. This simple grading is limited: it will not catch a very wide private range, and the port check is a plain string match.

8. Putting it together, and the entity columns

union WriteRows, DeleteRows
| join kind=leftouter SubNames on $left.SubscriptionId == $right.SubId
| extend Subscription = iff(isempty(SubscriptionName), SubscriptionId, SubscriptionName)
| extend AccountCustomEntity  = Caller,
         IPCustomEntity       = CallerIpAddress,
         ResourceCustomEntity = Entity
| project TimeGenerated, ChangeType, Exposure, DisplayName, Caller, CallerIpAddress,
          MfaSatisfied, PrincipalType, RoleUsed, Subscription, ResourceGroup,
          NSGName, RuleName, Priority, Direction, Action, Protocol,
          SourceIP, SourcePort, DestinationIP, DestPort, Description,
          Entity, CorrelationId,
          AccountCustomEntity, IPCustomEntity, ResourceCustomEntity
| order by TimeGenerated desc

Two details here saved me time. The leftouter join with a fallback means a subscription missing from the lookup still alerts, showing its ID rather than a blank. And the three CustomEntity columns must survive the final project. Drop them and incidents are created with no entities attached, with no warning at all.

The complete query

Here are all the pieces together, ready to paste into the Sentinel rule editor. Use the expand icon at the top right of the query box, because the collapsed editor is unusable for a query this long. Replace the example row in SubNames with your own subscription IDs and names.

let report = 1h;
let SubNames = datatable(SubId:string, SubscriptionName:string)
[
    "00000000-0000-0000-0000-000000000000", "Example subscription",
];
let WriteOps = dynamic([
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/WRITE",
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/SECURITYRULES/WRITE"
]);
let DeleteOps = dynamic([
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/DELETE",
    "MICROSOFT.NETWORK/NETWORKSECURITYGROUPS/SECURITYRULES/DELETE"
]);
let AllOps = array_concat(WriteOps, DeleteOps);
// padded pool: spans the full query period so Start rows are reachable
let Bodies =
    AzureActivity
    | where OperationNameValue in~ (WriteOps)
    | extend Req  = tostring(Properties_d.requestbody),
             Resp = tostring(Properties_d.responseBody)
    | extend Rank = iff(isnotempty(Req), 1, 2),
             Body = iff(isnotempty(Req), Req, Resp)
    | where isnotempty(Body)
    | summarize arg_min(Rank, Body) by CorrelationId
    | project CorrelationId, Payload = todynamic(Body);
// reporting window only: this is what generates alerts
let Confirmed =
    AzureActivity
    | where TimeGenerated > ago(report)
    | where OperationNameValue in~ (AllOps)
    | where ActivityStatusValue =~ "Success"
    | extend Entity = tostring(Properties_d.entity)
    | extend Ev = Authorization_d.evidence
    | project TimeGenerated, CorrelationId, OperationNameValue, Caller, CallerIpAddress,
              SubscriptionId, ResourceGroup, Entity,
              DisplayName   = tostring(Claims_d.name),
              RoleUsed      = tostring(Ev.role),
              PrincipalType = tostring(Ev.principalType),
              MfaSatisfied  = tostring(Claims_d["http://schemas.microsoft.com/claims/authnmethodsreferences"]) has "mfa";
// deletes: no payload, so rule detail is unknown
let DeleteRows =
    Confirmed
    | where OperationNameValue in~ (DeleteOps)
    | extend ChangeType = iff(OperationNameValue endswith "SECURITYRULES/DELETE",
                              "Deleted (rule)", "Deleted (whole NSG)")
    | extend NSGName  = extract(@"(?i)networkSecurityGroups/([^/]+)", 1, Entity),
             RuleName = extract(@"(?i)securityRules/([^/]+)", 1, Entity)
    | extend Priority = int(null), Direction = "n/a", Action = "n/a", Protocol = "n/a",
             SourceIP = "n/a", SourcePort = "n/a", DestinationIP = "n/a", DestPort = "n/a",
             Description = "", Exposure = "Review";
// writes: full rule detail
let WriteRows =
    Confirmed
    | where OperationNameValue in~ (WriteOps)
    | join kind=inner Bodies on CorrelationId
    | extend RuleSet = iff(isnotnull(Payload.properties.securityRules),
                           todynamic(Payload.properties.securityRules),
                           pack_array(Payload))
    | mv-expand Rule = RuleSet
    | extend p = Rule.properties
    | extend RuleName    = tostring(Rule.name),
             Etag        = tostring(Rule.etag),
             Direction   = tostring(p.direction),
             Action      = tostring(p.access),
             Protocol    = tostring(p.protocol),
             Priority    = toint(p.priority),
             Description = tostring(p.description)
    | extend ChangeType = iff(isempty(Etag), "Created", "Modified")
    | extend SourceIP = case(
            array_length(todynamic(p.sourceAddressPrefixes)) > 0,
                strcat_array(todynamic(p.sourceAddressPrefixes), ", "),
            array_length(todynamic(p.sourceApplicationSecurityGroups)) > 0,
                strcat("ASG: ", strcat_array(extract_all(
                    @'applicationSecurityGroups/([^/"]+)',
                    tostring(p.sourceApplicationSecurityGroups)), ", ")),
            tostring(p.sourceAddressPrefix))
    | extend DestinationIP = case(
            array_length(todynamic(p.destinationAddressPrefixes)) > 0,
                strcat_array(todynamic(p.destinationAddressPrefixes), ", "),
            array_length(todynamic(p.destinationApplicationSecurityGroups)) > 0,
                strcat("ASG: ", strcat_array(extract_all(
                    @'applicationSecurityGroups/([^/"]+)',
                    tostring(p.destinationApplicationSecurityGroups)), ", ")),
            tostring(p.destinationAddressPrefix))
    | extend DestPort = iff(array_length(todynamic(p.destinationPortRanges)) > 0,
                            strcat_array(todynamic(p.destinationPortRanges), ", "),
                            tostring(p.destinationPortRange)),
             SourcePort = iff(array_length(todynamic(p.sourcePortRanges)) > 0,
                            strcat_array(todynamic(p.sourcePortRanges), ", "),
                            tostring(p.sourcePortRange))
    | extend SourceIP      = iff(SourceIP == "*", "Any", SourceIP),
             DestinationIP = iff(DestinationIP == "*", "Any", DestinationIP),
             DestPort      = iff(DestPort == "*", "Any", DestPort),
             SourcePort    = iff(SourcePort == "*", "Any", SourcePort),
             Protocol      = iff(Protocol == "*", "Any", Protocol)
    | extend NSGName = extract(@"(?i)networkSecurityGroups/([^/]+)", 1, Entity)
    | extend Exposure = case(
          Direction =~ "Inbound" and Action =~ "Allow"
            and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0")
            and DestPort in ("22", "3389"),                          "Critical",
          Direction =~ "Inbound" and Action =~ "Allow"
            and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0")
            and DestPort == "Any",                                   "Critical",
          Direction =~ "Inbound" and Action =~ "Allow"
            and SourceIP in ("Any", "Internet", "0.0.0.0/0", "::/0"), "High",
          "Normal")
    | project-away Etag, Payload, p, Rule, RuleSet;
union WriteRows, DeleteRows
| join kind=leftouter SubNames on $left.SubscriptionId == $right.SubId
| extend Subscription = iff(isempty(SubscriptionName), SubscriptionId, SubscriptionName)
| extend AccountCustomEntity  = Caller,
         IPCustomEntity       = CallerIpAddress,
         ResourceCustomEntity = Entity
| project TimeGenerated, ChangeType, Exposure, DisplayName, Caller, CallerIpAddress,
          MfaSatisfied, PrincipalType, RoleUsed, Subscription, ResourceGroup,
          NSGName, RuleName, Priority, Direction, Action, Protocol,
          SourceIP, SourcePort, DestinationIP, DestPort, Description,
          Entity, CorrelationId,
          AccountCustomEntity, IPCustomEntity, ResourceCustomEntity
| order by TimeGenerated desc

The gotcha that returned empty names

The extract function is case-sensitive by default.

The resource ID in _ResourceId arrives lowercased, while Properties_d.entity keeps its original casing. A camel-case pattern run against lowercased text silently returns empty strings, which is the most likely cause of blank NSG and rule names. The (?i) flag at the start of each pattern handles both.

Closing the current-state gap

As covered in the last post, none of this sees rules that existed before logging began. Azure Resource Graph holds the rules as they are right now, and this query lists every inbound Allow rule open to the internet:

resources
| where type =~ "microsoft.network/networksecuritygroups"
| extend NSG = name, RG = resourceGroup
| extend Custom = iff(isnull(properties.securityRules),
                      dynamic([]), todynamic(properties.securityRules))
| mv-expand Rule = Custom
| extend p = Rule.properties
| extend Source = iff(array_length(todynamic(p.sourceAddressPrefixes)) > 0,
                      strcat_array(todynamic(p.sourceAddressPrefixes), ", "),
                      tostring(p.sourceAddressPrefix))
| extend Port = iff(array_length(todynamic(p.destinationPortRanges)) > 0,
                    strcat_array(todynamic(p.destinationPortRanges), ", "),
                    tostring(p.destinationPortRange))
| where tostring(p.direction) == "Inbound" and tostring(p.access) == "Allow"
| where Source in ("*", "Internet", "0.0.0.0/0", "::/0")
| project subscriptionId, RG, NSG, RuleName = tostring(Rule.name),
          Priority = toint(p.priority), Port, Source
| order by NSG asc

Sentinel analytics rules cannot query Resource Graph, so this cannot become a rule directly. I use it as a manual check, and the options for automating it are a Defender for Cloud export, a workbook, or a runbook that snapshots results into a custom table.

Before you trust it

Temporarily set report = 24h, run the query in Logs, and confirm that known changes from the last day appear with subscription names resolved and exposure graded. Then set report back to match the rule frequency. Next time: getting the scheduling and grouping right so this does not flood your queue.
